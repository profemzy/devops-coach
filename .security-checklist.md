# Security Checklist

This document outlines security best practices for the DevOps Coach project.

## ✅ Completed Security Measures

### 1. Sensitive Data Protection
- [x] `.env` files are gitignored (except `.env.example`)
- [x] `k8s/secret.yaml` is gitignored (template provided as `secret.yaml.example`)
- [x] All `*.pem`, `*.key`, `*.crt` files are gitignored
- [x] Credentials files are gitignored
- [x] Secret keys stored in environment variables, not hardcoded

### 2. Environment Configuration
- [x] Separate `.env.example` with safe defaults and documentation
- [x] Production secrets managed via Kubernetes Secrets
- [x] Base64 encoding for Kubernetes secrets
- [x] Docker secrets not included in image builds

### 3. Code Security
- [x] Password hashing with bcrypt
- [x] CSRF protection enabled (Flask-WTF)
- [x] SQL injection prevention (SQLAlchemy ORM)
- [x] Session security with secure secret key

### 4. Container Security
- [x] Multi-stage Docker builds (minimize attack surface)
- [x] Non-root user in containers (`python:python`)
- [x] Minimal base image (Python 3.14 slim)
- [x] No secrets in Docker images

## 🔒 Files That Should NEVER Be Committed

The following files contain sensitive information and are gitignored:

```
.env                    # Local environment variables
.env.local             # Local overrides
.env.production        # Production environment
k8s/secret.yaml        # Kubernetes secrets
*.pem                  # SSL/TLS certificates
*.key                  # Private keys
*.crt                  # Certificate files
*credentials*          # API credentials
```

## ⚠️ Before Committing

Always check:

```bash
# 1. Verify no sensitive files are staged
git status

# 2. Check what's being committed
git diff --cached

# 3. Search for common secret patterns
git diff --cached | grep -E "(api[_-]?key|password|secret|token)" -i

# 4. Verify gitignore is working
git check-ignore -v <filename>
```

## 🔑 Secret Management Best Practices

### Local Development
1. Copy `.env.example` to `.env`
2. Fill in your local development values
3. NEVER commit `.env`

### Kubernetes Deployment
1. Copy `k8s/secret.yaml.example` to `k8s/secret.yaml`
2. Encode values: `echo -n "value" | base64`
3. Update `k8s/secret.yaml` with base64-encoded values
4. NEVER commit `k8s/secret.yaml`
5. Apply: `kubectl apply -f k8s/secret.yaml`

### Secret Rotation
- Rotate secrets regularly (every 90 days recommended)
- Update both Kubernetes secrets and environment variables
- Restart deployments after secret updates

## 🛡️ API Key Security

### OpenAI API
- Use environment variable: `OPENAI_API_KEY`
- Restrict API key to specific IP ranges if possible
- Monitor usage for anomalies

### Tavily API
- Use environment variable: `TAVILY_API_KEY`
- Set appropriate rate limits

### Database Credentials
- Use strong passwords (20+ characters)
- Use Azure AD authentication for Azure PostgreSQL if possible
- Restrict database access by IP whitelist

## 📊 Security Monitoring

- [ ] Monitor API usage for anomalies
- [ ] Regular security audits of dependencies
- [ ] Review access logs periodically

## 📝 Incident Response

If secrets are accidentally committed:

1. **Immediate Action:**
   ```bash
   # Remove from current commit
   git reset HEAD~1
   
   # Add to gitignore
   echo "compromised-file" >> .gitignore
   
   # Recommit without sensitive data
   git add .gitignore
   git commit -m "security: Add sensitive file to gitignore"
   ```

2. **Rotate Compromised Secrets:**
   - Generate new API keys
   - Update environment variables
   - Update Kubernetes secrets
   - Restart services

3. **Clean Git History** (if already pushed):
   ```bash
   # Use git-filter-repo or BFG Repo-Cleaner
   # Contact repository administrator
   ```
